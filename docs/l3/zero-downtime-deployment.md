# Zero-Downtime Deployment & Rollback Runbook

**Статус:** Draft  
**Проект:** potok-app  
**Конформность:** EVO-L3 (Бесшовная эволюция)

---

## 1. Стратегии деплоя

### 1.1 Blue-Green Deployment

**Применимо к:** Backend (FastAPI)

**Принцип:** Две идентичные среды (Blue и Green). Активная среда обслуживает трафик, неактивная обновляется. После проверки — переключение маршрутизации.

**Процедура:**
1. Развернуть новую версию в неактивной среде (Green).
2. Запустить health check: `curl -f http://green:8000/health`
3. Запустить smoke-тесты: `curl http://green:8000/api/v1/journal/entries`
4. Переключить маршрутизацию (reverse proxy / load balancer) на Green.
5. Blue становится standby для быстрого отката.

**MTTR цель:** < 5 минут (переключение маршрутизации мгновенно).

### 1.2 Canary Deployment

**Применимо к:** Frontend (Flutter Web) и Backend

**Принцип:** Новая версия получает 10% трафика. При отсутствии ошибок — постепенное увеличение до 100%.

**Метрики успеха:**
- Error rate < 0.1%
- Latency p95 < 500ms
- WORM-лог без аномалий

## 2. Rollback Runbook

### 2.1 Быстрый откат Backend

```bash
# 1. Определить последнюю стабильную версию
git tag -l --sort=-v:refname | head -5

# 2. Откатить на предыдущий Git tag
git checkout v0.2.0  # пример

# 3. Пересобрать и развернуть
docker-compose up -d --build

# 4. Проверить health
curl -f http://localhost:8000/health
```

### 2.2 Откат миграций БД

```bash
# Alembic откат последней миграции
cd backend
alembic downgrade -1

# Проверка целостности
python3 tools/export-audit-bundle.py
```

### 2.3 Откат WORM-лога

**Важно:** WORM-лог неизменяем по дизайну. При откате приложения лог сохраняется для аудита. Новая версия начинает писать в тот же файл, продолжая цепочку хешей.

## 3. Health Checks

Все endpoints должны отвечать до принятия трафика:

| Endpoint | Ожидаемый ответ | Таймаут |
|----------|----------------|---------|
| `/health` | `{"status": "healthy"}` | 5s |
| `/passport` | Валидный JSON | 10s |
| `/sbom` | CycloneDX JSON | 10s |
| `/metrics` | JSON с метриками | 5s |

---

## 4. Метрики восстановления (MTTR)

| Сценарий | Целевое время | Метод измерения |
|----------|--------------|-----------------|
| Откат Backend | < 5 мин | Время от алерта до health check pass |
| Откат Frontend | < 10 мин | Время до стабильного билда |
| Восстановление БД | < 15 мин | Время от backup restore до первого запроса |
