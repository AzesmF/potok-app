# ADR-001: Выбор стека Flutter + FastAPI для MVP

## Статус
Принято

## Контекст
Необходимо разработать MVP кроссплатформенного приложения "Поток" (мобильные устройства + десктоп) с текстовым вводом и LLM-обработкой. Проект также является первым внешним пилотом методологии KON-MATRIX, что требует бесшовной интеграции Python-скриптов проверки зрелости (L1/L2) в CI/CD.

## Рассматриваемые альтернативы
1. React Native (мобайл) + Next.js (веб/десктоп через Electron).
2. Нативная разработка (Swift/Kotlin) + Python backend.
3. Flutter (мобайл + десктоп) + FastAPI (backend).

## Принятое решение
Выбран вариант 3: Flutter для фронтенда и FastAPI для бэкенда в формате Monorepo.

## Обоснование (Trade-offs)
- **Плюсы**: 
  - Единая кодовая база для iOS, Android, Windows, macOS, Linux (ускорение MVP).
  - Бэкенд на Python обеспечивает прямую синергию со скриптами KON-MATRIX (`scanner-l1.py`, `scanner-l2.py`), упрощая автоматизацию проверок Целостности (INT) и Чистоты (PUR).
  - FastAPI дает автоматическую генерацию OpenAPI-документации (Принцип Прозрачности).
- **Минусы**: 
  - Необходимость изучения/поддержки Dart для команды.
  - Размер бинарных файлов Flutter-приложения чуть выше нативных (некритично для MVP).

## Последствия
- Все будущие архитектурные изменения должны оформляться через новые ADR.
- CI/CD пайплайны будут настроены на запуск Python-скриптов KON-MATRIX на уровне всего репозитория.
